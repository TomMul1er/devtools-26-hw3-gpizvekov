# ДЗ 3. Подготовить CSV-сервис к запуску

Небольшая команда хранит результаты измерений в CSV-файлах.

> CSV – Comma-Separated Values, текстовый формат таблиц со значениями через запятую.

Сервис строит по этим данным отчёты. Сам сервис работает, но всё вокруг него сломано: `start.sh` не запускается, пакетная обработка не замечает повреждённые файлы, а после замены контейнера – пропадают отчёты.

Анализатор и сервер уже готовы. Вам же предстоит починить скрипты, упаковать сервис в Docker и собрать его вместе со шлюзом в Compose! По итогу сервисы должны научиться подниматься одной командой, отвечать на `/health`, принимать CSV-файлы и сохранять отчёты (даже после пересоздания контейнеров).

## Части задания

Советуем начать с [подготовки](tasks/00-setup.md). Далее – выполняйте части по порядку: каждая использует результат предыдущей.

| [3. HTTP](tasks/03-http.md) | Загрузка и обычные ошибки `submit.sh` (0,5)<br>Обрыв и сигналы (0,5)<br>`probe.sh` (0,5) | 1,5 |
| [4. Контейнер](tasks/04-docker.md) | Образ и HTTP (1)<br>Пользователь, контекст сборки и кэш (1) | 2 |

|  | **Итого** | **10** |

Каждый критерий засчитывается целиком или не засчитывается совсем. Грейдер запускает скрытые тесты на других данных, но проверяет только требования из текста заданий.

**Как себя проверить?**
После исправления повторите шаг и сверьте результат с требованиями. К примеру, после восстановления из архива откройте отчёт по прежнему ID и сравните содержимое. В частях 2, 3 и 6 `self-check.py` дополнительно проверяет по одному сценарию.

Форматы CSV и HTTP описаны в [справке](interfaces.md). Блоки «По желанию» можно пропустить без потери баллов.

## Обновление задания

Иногда в условии появляются уточнения. Один раз добавьте общий репозиторий.

```bash
git remote add upstream https://github.com/ai-hse/devtools-26-hw3-upstream.git
```

Перед работой и сдачей получите обновления в ветке `solution`. Если есть свои изменения, сначала сохраните их в коммит.

```bash
git pull --no-rebase --no-edit upstream main
```

Если возник конфликт, разрешите его и завершите слияние.

## Сдача

1. Чтобы сдать, закоммитьте решение в ветку `solution`. Список файлов, которые можно менять, есть в [подготовке](tasks/00-setup.md#что-можно-менять). В коммите допустимы только обычные файлы, без символических ссылок и подмодулей Git.
2. Проверьте готовность к отправке.
   ```bash
   bash tools/check-ready.sh
   ```

   Скрипт проверяет ветку, изменённые файлы, чистоту рабочего каталога и конфигурацию `Compose`.
3. После – отправьте ветку:
   ```bash
   git push -u origin solution
   ```
4. Откройте pull request из `solution` в `main`. Оставьте его открытым. После проверки грейдер сам закроет PR без слияния.
5. В разделе **Issues** откройте «Автопроверка HW3» с оценкой. **Работа считается сданной, когда вы отправили ссылку на этот Issue в [Peer Reviewer](https://peer-reviewer.pro/).**

Для пересдачи отправьте исправления в `solution` и откройте новый PR. Грейдер обновит оценку в том же Issue. Всего 10 попыток. Попытка тратится, только если грейдер выставил балл.
