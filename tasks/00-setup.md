# Подготовка и общие правила

Здесь вы настроите окружение, получите первый отчёт и прочитаете правила, общие для всех частей!

## Окружение

Для задания нужны Unix/Linux-окружение и следующие инструменты.

- Bash, `curl` и `tar`.
- Python 3.12 или новее с модулем `venv`.
- `Docker` и плагин `Docker Compose` с поддержкой `up --wait`.

На Linux работайте напрямую. Подойдёт и доступная вам учебная Linux-ВМ.

<details>
<summary>Mac и Windows</summary>

**Mac.** Запустите [Docker](https://docs.docker.com/desktop/setup/install/mac-install/) и работайте в терминале macOS.

**Windows.** Работайте в Linux-ВМ. Склонируйте репозиторий на диск виртуальной машины и выполняйте команды внутри неё.

</details>

### Проверить окружение

```bash
python3 --version          # 3.12 или новее
docker info                # без sudo и без ошибок
docker compose version
```

Если чего-то не хватает, воспользуйтесь инструкциями по [Python](https://docs.python.org/3/using/index.html), [Docker для Linux](https://docs.docker.com/engine/install/) и [Docker Compose](https://docs.docker.com/compose/install/).

## Первый отчёт

Здесь и во всех частях команды выполняются **в выбранном окружении из корня проекта**, если шаг не говорит другого.

1. Склонируйте свой репозиторий и создайте ветку `solution` от `main`. Добавьте общий репозиторий и получите обновления по [инструкции](../README.md#обновление-задания).
2. Создайте и активируйте виртуальное окружение, затем установите зависимости.

   ```bash
   python3 -m venv .venv
   source .venv/bin/activate
   python -m pip install -r requirements.txt
   ```

   В каждом новом терминале перед запуском Python выполните `source .venv/bin/activate` из корня проекта.
3. Прочитайте справку анализатора и сервера.

   ```bash
   python app/analyzer.py --help
   python app/server.py --help
   ```

   Формат CSV и пример отчёта описаны в [справке](../interfaces.md).

4. Создайте каталоги для результатов и обработайте первый файл.

   ```bash
   mkdir -p work/reports work/logs
   python app/analyzer.py samples/clean.csv --output work/reports/clean.json
   ```
5. Откройте `samples/clean.csv` и `work/reports/clean.json`. Каждая строка CSV-файла описывает один эксперимент, в числовых столбцах лежат его метрики! Сверьте число строк и хотя бы одну статистику с исходными данными. Позже такие отчёты будут создавать ваши скрипты.

Готовый [`.gitignore`](../.gitignore) исключает рабочие данные, окружение, логи, архивы и кэш Python.

## Что можно менять

**Можно:** заготовки `scripts/start.sh`, `batch.sh`, `submit.sh`, `probe.sh` и `backup.sh`, а также `app/settings.py`, `compose.yaml`, `gateway/nginx.conf` и ignore-файлы. `Dockerfile` и `.dockerignore` вы создадите в части 4.

**Нельзя:** остальной код в `app/`, примеры в `samples/`, `scripts/run-container.sh`, `gateway/Dockerfile`, программы в `tools/` и `.env.example`.

В части 4 вы временно измените Python-код и `requirements.txt`, чтобы проверить кэш сборки. Затем отмените эти две правки.

## Общие правила

### Скрипты

- Скрипты пишутся на Bash и запускаются через `bash`, как в примерах.
- Скрипт работает, из какого бы каталога его ни вызвали. Путь к проекту он определяет сам.
- Относительные пути в аргументах отсчитываются от каталога, из которого вызвали скрипт.
- Пути могут содержать пробелы.
- При неверном числе аргументов скрипт пишет сообщение в stderr и завершается с ненулевым кодом. Точные коды указаны в частях.
- Настройки скрипты получают через переменные окружения. Читать `.env` не нужно: он понадобится только Compose в части 6.

### Границы проверки

Основные тесты закрыты. Они используют небольшие CSV и архивы. Параллельную работу скриптов и изменение данных или прав во время копирования учитывать не нужно.

Если порт из примера занят, выберите свободный и используйте его до конца части.
