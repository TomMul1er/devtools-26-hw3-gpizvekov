# Часть 6. Собрать всё в Compose • 2,5 балла

Ну вот мы и на финишной прямой, хоть и длинной! Нашим коллегам нужен один адрес и для страницы, и для API. В этой части вы поставите перед API шлюз Nginx и соберёте оба сервиса в Compose. Менять нужно `compose.yaml`, `gateway/nginx.conf` и версию в `app/settings.py`. Исходники и Dockerfile шлюза уже готовы.

> **Nginx** – веб-сервер. В этом задании он принимает запросы и передаёт их сервису `api`.

![Запрос идёт через порт хоста в gateway, затем в api, а api хранит данные в томе reports](img/compose.svg)

Запускайте основной проект командой `docker compose -p hw3-lab …`. При работе над `compose.yaml` учитывайте три ограничения:

- Собирайте оба сервиса, `api` и `gateway`, из проекта. Других сервисов в нём нет. Контексты сборки и Dockerfile лежат внутри проекта. Код и конфигурация входят в образы.
- Сети и именованные тома принадлежат проекту. Не используйте внешние сети и тома, bind mount и `driver_opts`.
- Не задавайте `container_name`, `network_mode`, `privileged` и `devices`.

## 6.1. Связь сервисов: найти причину 502 • 0,75 балла

1. В начальном `compose.yaml` есть только `api`, опубликованный на `127.0.0.1:${WEB_PORT:-18090}:8080`. Добавьте именованный том проекта `reports` и подключите его к `/data`. Том `reports-data` из части 5 сам не перенесётся.
2. Создайте `.env` из `.env.example`. Если порт `18090` занят, задайте в `.env` другой свободный `WEB_PORT`.
3. Запустите API и дождитесь ответа `/health`.
4. Добавьте `gateway` из `gateway/service.example.yaml` и передайте ему публикацию порта `127.0.0.1:${WEB_PORT:-18090}:80`. API больше не публикует порт на хосте. Том сохраните. Примените обновлённую конфигурацию и запросите `/health` через шлюз.

Шлюз вернёт 502. Найдите причину и исправьте конфигурацию. В образ шлюза уже входят Nginx и `wget`.

**Требования:**

- Через один внешний адрес работают страница, загрузка CSV и чтение отчёта.
- Пути `/health` и `/reports` не меняются.
- Шлюз обращается к сервису по имени `api`.

**Самопроверка.** Оставьте сервисы запущенными и выполните:

```bash
python tools/self-check.py compose
```

Проверка загрузит CSV через шлюз и прочитает отчёт. Отчёт останется в томе.

## 6.2. Готовность и восстановление • 0,75 балла

### Дождаться готовности

Переменная `STARTUP_DELAY_SECONDS=15` включает 15-секундную инициализацию: HTTP уже доступен, но `/health` и операции с отчётами отвечают 503. Код сервера менять не нужно.

![Шкала времени: API инициализируется и отвечает 503, затем становится healthy. Шлюз запускается после готовности API. up --wait возвращает управление, когда оба сервиса healthy](img/startup.svg)

1. Удалите контейнеры проекта, том сохраните. Задайте задержку `15` и запустите проект. Сравните состояние контейнеров, ответ `/health` через шлюз и логи до и после того, как API стал готов.
2. Настройте порядок запуска и healthcheck обоих сервисов по требованиям ниже.
3. Снова удалите контейнеры, сохранив том, и запустите:
   ```bash
   docker compose -p hw3-lab up -d --build --wait --wait-timeout 60
   ```

**Требования:**

- Шлюз запускается только после того, как API успешно ответил по HTTP.
- Healthcheck API учитывает инициализацию.
- Healthcheck шлюза подтверждает, что работает вся цепочка до API.
- Сразу после успешного `up --wait` первый запрос через шлюз работает.

Проверка меняет задержку от 0 до 15 секунд. Таймаут в 60 секунд относится к ожиданию готовности, а не к сборке. После проверки верните задержку к `0`.

### Восстановиться после отказа API

Теперь попробуйте отключить автоматический перезапуск обоих сервисов. Остановите только контейнер `api`, не удаляя его. Сравните состояние процесса шлюза, его статус healthcheck и HTTP-ответ.

> **На подумать.** Что произошло автоматически, а чего healthcheck не делает?

Запустите тот же контейнер API.

**Требование:** в течение 60 секунд после запуска API у обоих сервисов восстанавливаются HTTP-доступ и статус `healthy`. Перезапускать шлюз вручную не нужно.

## 6.3. Обновление • 0,5 балла

Загрузите через шлюз `samples/clean.csv` и `samples/batch/missing_values.csv`. Сохраните ID обоих отчётов. После каждого шага ниже проверяйте, что их ID и содержимое не изменились.

1. **Окружение.**
   - Задайте API `INSTANCE_NAME=first` и проверьте значение в `/health`.
   - Измените его на `second` и выполните только `restart api`. Сравните ответ `/health` и ID контейнера с прежними.
   - Примените изменённую конфигурацию. Снова проверьте ответ, ID контейнера, HTTP и `healthy`: всё должно восстановиться за 60 секунд.
2. **Код.** В `app/settings.py` измените версию с `1` на `2`. Сравните обычный `restart` с обновлением после пересборки. После пересборки API должен сообщить версию `2`.
3. **Хранилище.** Выполните `down` без `-v` и снова запустите проект. По справке выясните, что изменил бы флаг `-v`. Рабочий том не удаляйте.

## 6.4. Независимость и лимиты • 0,5 балла

К сожалению, мир суров. И ресурсы могут быть ограничены! Попробуйте и вы ограничить API одним CPU и 256 MiB памяти. Из того же каталога запустите второй проект с новым именем и другим свободным портом. Например:

```bash
WEB_PORT=18091 docker compose -p hw3-second up -d --build --wait
```

У второго проекта `GET /reports` должен вернуть `[]`. У первого по-прежнему читаются оба контрольных отчёта. После проверки остановите второй проект.

**К сдаче.** Оставьте версию `2`, `INSTANCE_NAME=second` и `STARTUP_DELAY_SECONDS=0`. У обоих сервисов включён healthcheck и выключен автоматический перезапуск.

**По желанию · Как открыть сервис с ВМ в браузере ноутбука?**

Если проект запущен на удалённой Linux-ВМ, проверьте на ней `/health` через порт шлюза. Теперь откройте тот же адрес с `127.0.0.1` на ноутбуке. К какой машине обращается браузер?

На ноутбуке настройте локальный SSH-туннель со свободного порта на порт шлюза на ВМ. Пример команды есть в [семинаре 5, раздел «Проброс портов»](https://github.com/aesedeu/devtools-course/blob/2026/lecture05%20-%20%D0%A1%D0%B5%D1%82%D1%8C%20SSH%20HTTP%20WebSocket%20gRPC/%D1%81%D0%B5%D0%BC%D0%B8%D0%BD%D0%B0%D1%80.md#проброс-портов). Откройте страницу через туннель, загрузите `samples/clean.csv` и найдите отчёт по его ID с ВМ. Закройте туннель. Откуда теперь доступен сервис?
