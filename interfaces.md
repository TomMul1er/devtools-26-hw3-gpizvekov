# Справка по готовому приложению

## CSV

- Кодировка UTF-8, BOM допустим. Разделитель полей – запятая, десятичный разделитель – точка.
- Первая строка ровно `experiment,accuracy,latency_ms`.
- В каждой следующей строке три поля. Нужна хотя бы одна строка данных. Пустые строки между записями не допускаются.
- Обычные правила CSV-кавычек поддерживаются.

**Столбцы**

- `experiment` – имя эксперимента. После удаления пробелов по краям оно не должно быть пустым. Имена могут повторяться.
- `accuracy` и `latency_ms` – конечные числа. Пустое поле или поле из одних пробелов считается пропуском.

Весь CSV считается некорректным, если в нём есть `NaN`, бесконечность, текст вместо числа или строка с неправильным числом полей.

Пример отчёта для `samples/clean.csv`.

```json
{
  "row_count": 3,
  "columns": {
    "accuracy": {"count": 2, "missing": 1, "min": 0.8, "max": 0.9, "mean": 0.85},
    "latency_ms": {"count": 3, "missing": 0, "min": 80.0, "max": 120.0, "mean": 100.0}
  }
}
```

- `count` считает значения без пропусков, `missing` считает пропуски.
- Среднее округляется до шести знаков после точки.
- Если в столбце пропущены все значения, `count=0`, а `min`, `max` и `mean` равны `null`.
- Форматирование JSON и порядок ключей не важны.
- Расчёты детерминированы. Исходный файл не меняется.

## Анализатор как команда

Из корня проекта:

```bash
python app/analyzer.py samples/clean.csv --output work/report.json
```

Пути в аргументах отсчитываются от текущего каталога. Родительский каталог выходного файла должен существовать.

| Код | Когда | Что происходит |
|---|---|---|
| `0` | Успех | JSON записан в выходной файл, stderr пуст |
| `1` | Ошибка в CSV, ошибка чтения или записи | Пояснение в stderr |
| `2` | Ошибка аргументов | Пояснение в stderr |

Если CSV некорректен, прежний отчёт сохраняется. При ошибке записи файл может оказаться неполным.

## Запуск HTTP API

```bash
python app/server.py
```

Параметры передаются через окружение, позиционных аргументов нет. `--help` выводит справку и не запускает сервер.

| Переменная | По умолчанию | Значение |
|---|---|---|
| `HOST` | `127.0.0.1` | Адрес, на котором сервер принимает подключения |
| `PORT` | `8080` | Целое число от 1 до 65535 |
| `DATA_DIR` | `work/data` внутри проекта | Каталог хранилища. Передавайте абсолютный путь |
| `INSTANCE_NAME` | `csv-reports` | Метка экземпляра в ответе `/health` |
| `STARTUP_DELAY_SECONDS` | `0` | Задержка готовности при каждом запуске, от 0 до 15 секунд |

Версию задаёт константа `VERSION` в `app/settings.py`.

Сервер читает настройки при запуске и работает на переднем плане.

При старте сервер создаёт каталог данных, внутри него каталог `reports/` и журнал `uploads.jsonl`. Если писать в каталог данных нельзя, сервер завершается с ненулевым кодом, не начав обслуживать запросы.

Пока идёт задержка готовности, сервер принимает HTTP-запросы, но `/health` и `/reports…` отвечают 503. После задержки `/health` проверяет, что в хранилище действительно можно писать.

## HTTP

Каждый ответ API содержит заголовок `X-Request-ID`. Тот же ID сервер пишет в stderr вместе с методом, путём и статусом. `GET /` возвращает HTML, остальные ответы из таблицы возвращают JSON с заголовком `Content-Type: application/json`. Максимальный размер тела POST – 2 MiB.

| Запрос | Статус и тело |
|---|---|
| `GET /` | 200, HTML-страница загрузки и просмотра отчётов |
| `GET /health` | 200, `{"status":"ok","version":1,"instance":"csv-reports"}` |
| `GET /health` во время задержки | 503, те же поля, но `status` равен `starting` |
| `POST /reports`, поле формы `file` | 201, отчёт анализатора с дополнительными полями `id` и `filename` |
| `POST /reports`, некорректный CSV или нет файла | 422, `{"error":"пояснение"}` |
| `POST /reports`, другой `Content-Type` | 415, `{"error":"пояснение"}` |
| `GET /reports` | 200, массив полных отчётов. В новом хранилище он пуст |
| `GET /reports/<id>` | 200, тот же объект, что вернул POST. Если такого ID нет, 404 |
| `DELETE /reports` | 405, JSON с ошибкой и заголовок `Allow` с допустимыми методами |
| Неизвестный путь | 404, JSON с ошибкой |

Пример загрузки из корня проекта.

```bash
curl -i -F 'file=@samples/clean.csv' http://127.0.0.1:8080/reports
```

`-F` отправляет форму методом POST. Знак `@` перед путём передаёт содержимое файла в поле `file`.

**Отчёты**

- `id` – строка из 32 шестнадцатеричных символов. Каждый успешный POST создаёт новый отчёт, даже если CSV тот же.
- `filename` – имя загруженного файла без пути.
- Ответ 201 содержит заголовок `Location: /reports/<id>`.
- Порядок отчётов в `GET /reports` не гарантирован.

**Хранилище**

- Отчёт лежит в `DATA_DIR/reports/<id>.json`, журнал загрузок в `DATA_DIR/uploads.jsonl`. Исходный CSV не сохраняется.
- Каждая строка журнала – JSON с полями `id`, `filename` и `request_id`.
- Контейнер записывает отчёты от своего UID, пользователь хоста может их читать.
- Версии 1 и 2 используют один формат хранилища. Если каталог данных сохранён, прежние отчёты доступны по тем же ID.

## Имитация сервера для отказов

```bash
python tools/http-fixture.py --host 127.0.0.1 --port 8090
```

Имитация обслуживает запросы параллельно: медленный запрос не блокирует `/ok`. Данные основного API она не использует.

| Маршрут | Поведение |
|---|---|
| `GET /ok` | 200 с коротким JSON |
| `GET /unavailable` | 503 с JSON ошибки |
| `GET /slow` | 200 через 15 секунд |
| `GET /redirect` | 302 с `Location: /ok` |
| `POST /reports` | По умолчанию 201 с намеренно обрезанным телом и завышенным `Content-Length` |
| `POST /reports` с `--upload-mode complete` | Полный ответ 201 без задержки |
| `POST /reports` с `--upload-mode slow` | Полный ответ 201 через 15 секунд |
